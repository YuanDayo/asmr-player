# 动效规范（Motion Spec）

文档版本：1.0
用途：约束所有动画的时长、曲线、组合方式，以及「什么时候不该有动画」。
配套：[UI-SPEC.md](UI-SPEC.md)（界面令牌与手势）、[AGENTS.md](../AGENTS.md)（AI 硬规则）。

---

## 1. 三个入口，不许自己拼

业务代码只允许从 `ui/theme/Motion.kt` 取 spec、从 `ui/theme/MotionTransitions.kt` 取转场。

| 入口 | 用在什么上 | 曲线 | 默认时长 |
| --- | --- | --- | --- |
| `Motion.standard(base)` | 尺寸、颜色、位置等普通变化 | FastOutSlowIn | 220 |
| `Motion.enter(base)` | 元素进入画面 | 减速 | 220 |
| `Motion.exit(base)` | 元素离开画面 | 加速 | 150 |
| `Motion.ambient()` | 装饰性循环（均衡器条） | 线性 | 900，不吃倍率 |

时长档位只有三个：`SHORT=150` / `MEDIUM=220` / `LONG=400`。
再需要别的就说明这个动作本身没想清楚，先想清楚，别加档。

`ambient()` 故意不响应「简化动效」：无限循环动画一旦把时长压到 0，会变成「每帧一轮」的自转，
比不动画面更耗电。

## 2. 具名转场

| 名字 | 形态 | 用在哪 |
| --- | --- | --- |
| `asmrEnter()` / `asmrExit()` | 高度 + 透明度 | 卡片这类**内容在容器里**的进出场 |
| `collapseEnter()` / `collapseExit()` | 高度 + 透明度（标准曲线） | 页面骨架收放：头部、四格、走带 |
| `tabTransition(forward)` | 旧页 90ms 淡出 → 新页晚 90ms 起跑（减速 + 1/12 屏） | 一级标签切换 |
| `playerTransition(enteringPlayer)` | 同上串行交接，只保留纵向 1/40 屏 | 进 / 出播放页 |
| `fadeThrough()` | 只淡不位移 | 同一位置换内容：播放/暂停图标 |
| `popIn()` / `popOut()` | 淡入 + 轻微缩放 | 浮层提示（「回到当前进度」胶囊） |
| `sharedBoundsSpec()` | 减速（与 `tabTransition` 同一条） | 共享元素飞行 |

两条经验写在代码注释里也写在这里：

- **同一位置换内容用 `fadeThrough`**。播放/暂停如果叠位移或缩放，会被看成「两个图标在打架」；
  纯淡入淡出才像同一个按钮换了状态。
- **`collapse*` 用标准曲线而不是减速**。它驱动的是「内容区在长大」，减速会让最后一帧发飘。

### 2.1 切页为什么这么调

- **切页是串行交接，不是交叉淡变**（2.5.5-beta9）。两页同时半透明只在「两边都是不透明整块」时
  成立；我们的卡片是半透明的（`LocalCardAlpha` 0.78）、栏是磨砂的，叠起来就是两张页面糊在
  一起 —— 曲库的筛选 chip 压在播放页封面上、迷你条的灰底压在走带上，用户会直接说
  「不连贯 / 阴影变成方块」。现在是旧页 90ms 淡掉、新页晚 90ms 起跑，交接缝约 5 帧。
  改这条之前先想清楚：**任何交叉淡变都会把半透明内容叠成灰块**。
- **位移只给进场那一层，1/12 屏**。1/8 屏（60dp）加淡入是「两张纸在互相错开」，注意力全在位移上。
  两层同时位移就是「错位」，一层位移才是「落位」。
- **进场用减速曲线**。起步就有速度、最后一段慢慢落位，这是「跟手」的来源；
  标准曲线两头都慢，同一时长看起来更机械。
- **`sharedBoundsSpec()` 必须与进场同一条曲线**：封面是在页面上飞的，页面在平移，
  两者曲线不同步就会看到封面在屏幕上漂。
- **顶栏标题不做换字动画**。标题是「标签」不是「内容」，标签栏里硬换字本来就是常态；
  而任何宽度补间都会让整条顶栏（logo、装饰色块）逐帧重新布局，只换来 150ms 的淡入。
- **底栏图标的选中态只插值颜色**。试过再加一个 `graphicsLayer` 缩放（「图标落位」），
  观感几乎看不出，代价是导航胶囊里多出三个逐帧重绘的图层：同一台模拟器同一个包，
  曲库↔设置的掉帧 5.3% → 14~16%。删掉缩放后回到 5.3%。

### 2.2 迷你条：透明度用 `FLASH`，位移用 `MEDIUM`

`asmrEnter()` 的 `expandVertically` 会裁掉超出边界的东西，而阴影整个画在边界外 ——
进场最后几帧只剩一条硬边，看起来就是「阴影突然出现」。所以迷你条用
`AnimatedVisibility` +「淡 + 下沉」，尺寸不参与动画。

两个时长故意不同，这是 beta9 定的：

| 通道 | 时长 | 为什么 |
| --- | --- | --- |
| 透明度（exit） | `FLASH` 90ms | 眼睛要在走带落位前看不到它，否则就是「幽灵条压在播放键上」 |
| 位移（exit） | `MEDIUM` 220ms | 决定节点在组合里活多久；共享元素靠它撑着，提前消失封面就从「飞」变「跳」 |

**必须是真正的 `AnimatedVisibility`**：封面的共享元素要「一端退场、另一端进场」才配对
（`SharedElement.updateMatch` 要求 `states.size > 1 && hasVisibleContent`）。用
`animateFloatAsState` 自己驱动 alpha 会让两端一直在场，等于没有交接，封面只能硬跳。

高度**不参与**动画：导航胶囊贴底排，迷你条让位不会推动它，于是 `LocalBottomBarInset`
只在「在不在」翻转时变一次，页面不会逐帧重排。

### 2.3 封面飞行时不许留底板

被共享的只有封面图片，槽位那层灰色底板（`surfaceVariant`）留在原地 —— 抓帧能看到
「目标尺寸的灰方块 + 小一号的封面叠在它左下角」。`LocalCoverFlight` 在进出播放页的窗口里
把两端的底板都隐掉，飞的过程里只有封面本身。窗口时长要乘 `MotionDurationScale`：
Compose 的 tween 会被系统动画缩放拉长，`delay` 不会，否则慢放（或用户把动画调到 2 倍）时
底板会在飞行中途提前回来。

### 2.4 播放页两档：一个进度驱动全部

播放页有折叠（沉浸封面 + 底部卡片）与展开（完整布局）两档。**它不是两套界面**，而是同一张
卡片的长高：曲目卡、四格、台本、走带都是同一批实例，只有高度、圆角、底色在变。

实现上有三条硬约束，全是踩出来的：

1. **只允许一个动画量**。卡片高度、台本卡高度、圆角、底色、背景遮罩、底部让位全部由
   `progress`（0 折叠 / 1 展开）算出来。曾经用「实测内容高度当动画目标」，等于两个来源互相追：
   实测值在进页动画里每帧都变，把它塞进 `LaunchedEffect` 的 key 就是每帧取消重启动画，
   持续掉帧到 ANR。
2. **组合阶段不许读 `progress`**。它每帧都变，在组合里读一次就是整页重组一次。所有消费点
   都写在 `layout` / `drawWithContent` / `graphicsLayer` 的 lambda 里（相位内读 State 只失效
   布局或重绘）。
3. **布局高度恒定 = 整页，卡片的「多高」只体现在绘制裁剪上**。按折叠高度去限制 Column 时，
   走带（最后一个孩子）拿不到足够约束，量出来的高度永远偏小，于是「压得越矮 → 量得越小 →
   压得更矮」，走带被裁掉且永远修不回来。

**测量死锁**（给后来人）：台本卡的高度是「剩余空间」，它排在走带前面。一旦固定块总和暂时
偏小（切页回来第一帧，孩子刚挂上还没量到），台本会把空间吃光、走带被量成 0，而走带高度
正是那个总和的一部分 —— 自己把自己锁死在 0 上，整排走带消失。解法是给弹性块一个
`reserve`（`sheetHeight(reservePx = …)`），保证它永远给走带留出至少一格。

### 2.5 可打断（interruptible）

用户会在动画演到一半时再点一次、按返回、或者往回拖。所有转场都必须从**当前状态**继续，
不许跳回起点：

- 用 `Animatable` / `animate*AsState` / `AnimatedContent` / `AnimatedVisibility` —— 它们
  重新给目标时会从当前值接着走。播放页卡片的拖动是 `snapTo` 跟手、松手 `animateTo` 归位。
- **松手归位必须由松手那一侧收尾**，不能指望 `LaunchedEffect(state)` 兜底：拖一点点就松手时
  `setState(false)` 是个 no-op（状态没变），effect 不会重跑，卡片会僵在半路。
- **不要用「先 `delay` 再改状态」伪造动画**：切页中途返回时它不会被打断，会跳。
  延迟只用于「等另一层让开」这类节奏控制，且时长要乘 `MotionDurationScale`。
- 显示/隐藏一律走 `AnimatedVisibility`，不要 `if (...) 组件()`：`if` 是硬切，而且会把
  退出动画需要的高度直接抹掉（`fixedOf` 这类测量会跟着抖）。

## 3. 降级与开关

三层，从外到内：

1. **系统「动画时长缩放」= 0**：系统层面 Compose 动画本身就是直切。
   共享元素额外用 `Animations.enabled()` 判断后整体关掉（`sharedBounds` 在 0 时长下会留下
   覆盖层残影，不能只依赖框架）。
2. **设置里「简化动效」**：`Motion.scale = 0.5`，所有 tween 时长减半。给「系统没关动画、
   但觉得切页花哨」的人。
3. **`Motion.scale = 0`**：理论上的直切，目前没有 UI 暴露，留着给「性能诊断」用。

`AsmrTheme` 在 `SideEffect` 里写 `Motion.applyScale(...)`：组合可能被丢弃重试，副作用要落到树上再做。

为什么是全局变量而不是 CompositionLocal：spec 大量在 `transitionSpec = {}`、`animateDpAsState(...)`
这类**非可组合**位置构造，那里读不到 CompositionLocal；而 spec 又必须每次重建才让开关立刻生效。

## 4. 台本放大为什么是「同一张卡长大」

阅读模式以前在布局里是一个独立分支：整个 `Crossfade` 子树被摘掉，换成 `ReadModeBar + content()`。
后果有两个，都很难看：

1. `ScriptPanel` 被重新挂载，`LazyListState` 归零 —— 放大后回到台本开头，读到哪里全丢；
2. 没有任何过渡，屏幕上是一次硬切。

现在的结构（竖屏非大图档）：

```text
Column
├─ AnimatedVisibility(!reading && !showPlaylist) { 头部 + 四格 }   ← collapseExit 收起
├─ Box(weight(1f)) { contentCard() }                              ← 同一个实例，靠腾出的高度长大
└─ AnimatedVisibility(!reading) { 走带 }                          ← collapseExit 收起
```

卡片自身再插值两个值：外扩边距 `Spacing.lg → Spacing.xs`、圆角 `Radius.xl → Radius.md`，
卡头则在阅读态换成 `ReadModeBar`（退出按钮、曲名、时间、播放暂停 + 2dp 进度线）。
所以放大就是「同一张卡在长大」，不是「换了一套界面」。

## 5. 共享元素的 key 必须带曲目

`sharedNowPlayingCover()` 的 key 是 `now-playing-cover:<曲目绝对路径>`，由 `AppRoot` 在
`LocalNowPlayingTrack` 里一处下发（迷你条与播放页都在它下面）。

key 固定成常量时会出这个错：在播放页换一首再返回，新封面会从**上一首**的矩形起飞。
带上 trackId 后，换歌时两端 key 不相等，共享元素自然不配对，退化成普通进出场 —— 这就是
「退出播放页时换歌可降级」的实现方式，不需要额外的标志位。

## 6. 列表连续

- 稳定 key 优先：曲库作品用 `path`，曲目用 `t:" + path`，搜索结果用 `hit:" + path`；
  台本行用 `"<startMs>#<原行号>"`（同一声内可能出现相同时间戳，必须补行号）。
- 位置动画（`Modifier.animateItem()`）只给**单次可见条目有限**的列表：曲目列表、搜索结果、播放队列。
  曲库作品列表没加 —— 筛选时可能整屏换内容，几千个条目同时做插入/移动动画是纯亏。
  这条是压测后的决定，不是遗漏（见第 7 节）。
- `animateItem()` 只能构造在 `LazyItemScope` 里，所以 `TrackRow` 收一个 `modifier` 参数由调用处传。

## 7. 性能记录与回归清单

> 用 `scripts/jank_probe.sh`（分三组读 `gfxinfo`）与 `scripts/ui_verify.sh transition`（动画放慢 10 倍连拍）
> 采集。模拟器是 x86 软件光栅，绝对值比真机差，只看**同环境前后对比**。

**2.5.5-beta2 的实测**（同一台模拟器，`jank_probe.sh` 已加「预热两轮再计量」——冷启动后
扫描 / 封面解码还在跑，谁排在第一组谁替它们背锅，同一个包「曲库↔设置」能测出 5% 和 25%）：

| 组 | 掉帧率 | beta1 之后的两处改动 |
| --- | --- | --- |
| 曲库 ↔ 设置 | 5.3% | 底栏图标去掉 `graphicsLayer` 缩放（此前 14~16%） |
| 曲库 ↔ 播放 | 6.3% | 迷你条不再 `expandVertically`（阴影不再被裁） |
| 播放 ↔ 设置 | 6.4% | 切页位移 1/8 → 1/12（进）/ 1/24（退） |

结论：**在这个界面里，最贵的从来不是位移，而是「让本来就有的东西每帧重画」**——
给三个图标加一个看不见的缩放，比整页平移 40dp 贵三倍。

历史数据，只为对照：

- 2.5.4（修完「切页顿一下」）：曲库↔设置 6.4%、曲库↔播放 7.6%、播放↔设置 6.5%，Slow draw 99 → 25。
- 2.5.5-beta1 **没采到数据**：模拟器连续冷启动后 guest 卡死（`sys.boot_completed` 恒空），
  `-wipe-data` 能救回来但会把测试曲库和「正在播放」状态一起清掉，台本放大入口的自动化
  （`ui_verify.sh read`）点不到按钮。要补这一项就跑 `WIPE=1 SEED=1 bash scripts/ui_verify.sh <apk> <out> read`。

### 回归清单

每次改动动效都要过一遍：

- [ ] 曲库 ⇄ 播放 ⇄ 设置 三向切换：底栏不跳、迷你条淡出（阴影跟着一起收，不出现硬边）、封面能飞
- [ ] 播放页走带：不被导航胶囊压住（下端至少留 12dp），中间那颗播放键与屏幕正交对齐
- [ ] 播放页三档（紧凑 / 大封面 / 全页大图）互相切换不跳版
- [ ] 台本放大 / 退出：卡片连续长大、滚动位置不丢、退出能回原位置
- [ ] 播放列表 / 图片面板铺满与还原
- [ ] 换皮肤、换强调色、明暗切换：不闪、不残留上一套颜色
- [ ] 系统关闭动画（开发者选项 animator_duration_scale=0）：功能照常，只是没有动画
- [ ] 设置里「简化动效」开启后，动画明显更短但不错位
- [ ] 长台本跟读 3 分钟：跟随不抢滚动、手动滚动后能「回到当前进度」
- [ ] 1000+ 条目的列表筛选：不卡死、不出现条目重叠
